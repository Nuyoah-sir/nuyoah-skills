## 测试方法与基础设施说明

### 测试流程
1. 运行对应 `solve_X.sh` 启动 Docker 容器（PostgreSQL + Kafka）和 Spring Boot 应用
2. 执行 `test.sh` 进行黑盒 HTTP 测试（60 项断言，12 个测试组）
3. 记录结果并清理环境

### 基础设施
- **PostgreSQL**：`postgres:16-alpine` Docker 容器，端口 5432
- **Kafka**：本地构建的 `kafka-local:latest` 镜像（基于 `postgres:16-alpine` + OpenJDK 17 + Kafka 3.8.0 KRaft 模式），端口 9092
- **Java**：OpenJDK 21.0.7，Maven 3.9.10

### 已识别的非模型问题
1. **kafka-local 镜像 KRaft 配置错误**：`controller.listener.names=CONTROLLER` 但缺少对应的 CONTROLLER listener，导致容器启动失败。通过添加 `CONTROLLER://0.0.0.0:9093` listener 修复（属于基础设施，非模型代码问题）
2. **test.sh 的 json_get 函数**：在无 `jq` 环境中，Python fallback 无法正确解析嵌套 JSON 路径（`.data.sku`），修复为递归遍历 JSON 树。同时处理了 JSON null → Python None → 空字符串的转换
3. **Git Bash 路径转换**：Windows Git Bash 的 MSYS2 路径转换导致 `docker exec` 中路径被错误转为 Windows 路径（如 `/opt/kafka/bin/kafka-topics.sh` → `E:/StudyTool/Git/opt/kafka/bin/kafka-topics.sh`），通过 `sh -c` 包装命令解决
