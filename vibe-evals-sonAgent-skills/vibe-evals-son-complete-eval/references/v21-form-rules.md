# V2.1 评分表单规则

## 题目级共享节

先独立评每个模型总体印象（0–4，0.5 步长），全部定完后才排序。Rank 第一键是总体印象降序；总体印象相同才用可比 Rubric 表现得分；两键相同才并列。不同 rubric 集无法建立共同口径时保留并列，不强排。

N=1 仍保留排序节，档位 1，并写“单模型，无同场比较/无排序”。排序理由只写 1–3 个可观察的整体交付分水岭，不引用模型名气或“上游排在前面”。

洞察写最大跨模型差异与能力边界，不复述分数和排序。难点和思路写题目难点及考察设计。

## 每模型

- 总体印象：不是维度平均；与平均不一致时在反馈中说明可观察原因。
- G1：显式指令与约束类 rubric。
- G2：功能/bug rubric 与 4W1H。
- G3：修复轨迹与 debug 次数；多轮 3 次、单轮 5 次为当前上限口径。
- S1：前端视觉题适用，依据图形/media rubric 与人工视觉意见。
- R1：模糊需求题按首轮是否提问门控；首轮未提问标 N/A，不换算低分。
- A1：按当前本地政策默认 N/A；若权威 V2.1 文档已更新，先登记政策版本和人工确认，不静默沿用旧口径。

不适用维度写 `N/A【不适用：依据】`，删除数字建议和勾选栏。所有适用维度与总体印象写 `【建议 x，待人工确认】`。

## 分数纪律

3 分是验收线；不是 3 必须有加/扣分事实。0 分谨慎，不因 debug 次数单独全给 0。总体印象是 Rank 主键，不由 Rubric 得分或 pointwise 平均反推。

## 文字反馈

速记风格只写事实 + 括号证据 + rubric 编号：Pros 2 条，Cons 最多 5 条，Style/Fingerprints 1 条。合并同类项，删除元标注、日期前缀、解释从句和重复措辞。

Cons 示例结构：`- 缺陷名（关键数值/函数名）：事实——R1-03/07=0。`

Pros 用顿号串联达标事实与 rubric；Style 一句话写相对独特行为。全员共有行为不算指纹。

## 标签

只从 `V2.1标签库.md` 选择。有突出证据的可多选，没有不硬贴。Pros/Cons 可同时出现看似矛盾标签，但须有各自证据。自定义标签只能由人工在库无匹配时提出。

## 交叉检查

所有建议分依据进入 Pros/Cons；N/A 有依据；排序键正确；表现得分口径可比；洞察不是分数复述；表单数字与 scored rubrics 和反馈报告一致。
