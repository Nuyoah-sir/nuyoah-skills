# Vibe Evals 跨机器证据技能安装与操作手册

## 你最终要复制什么

正常情况下，第三方机器只需要复制回两个文件：

- `{题目}-evidence-bundle.zip`
- `{题目}-evidence-bundle.zip.sha256`

如果本机提出补证，再把很小的 `evidence_requests.json` 传回第三方，之后复制一个 delta ZIP 回来。无需复制完整题包。

## 1. 在第三方机器安装

先确认第三方机器具备：Codex 能读取本地文件并发现用户技能、PowerShell 5.1+、Python 3.10+（命令 `py` 可用）。模型代码的动态执行还需要独立提供真正的无网沙箱；没有沙箱仍可完成静态证据包。

把本分发包解压到任意新目录，在该目录打开 PowerShell：

```powershell
$PSVersionTable.PSVersion
py -c "import sys; assert sys.version_info >= (3,10); print(sys.version)"
Set-ExecutionPolicy -Scope Process Bypass
.\install-third-party.ps1
```

脚本安装：

- `vibe-evals-son-evidence-export`
- `vibe-evals-son-evidence-supplement`

如果已有同名技能，脚本默认停止。确认要升级时使用 `-Force`；旧技能会先移动到技能发现根目录同级的 `codex-skill-backups`，不会直接删除，也不会留下可被 Codex 重复发现的同名旧技能。

如果你用 `-SkillsRoot` 安装到自定义目录，后续命令中的 `$SkillRoot` 也必须改为安装脚本实际打印出的技能路径；手册默认值只适用于标准 `~/.codex/skills`。

安装后重启 Codex 或新建任务。

## 2. 第三方机器首次运行

建议直接复制下面提示词，只替换两个路径：

```text
使用 $vibe-evals-son-evidence-export 处理题包
E:\工作\未来小猎\E3后端评测-CodingAgent题0812\_rubric修改\TestCode\双曲空间的推箱子游戏\双曲空间的推箱子游戏-0908

输出根目录（不是 bundle 目录）例如：
E:\vibe-evals-handoff

请自动创建唯一 RUN_ID，最终固定为 OUTPUT_ROOT\RUN_ID\bundle；ZIP 放在 OUTPUT_ROOT\RUN_ID，不能放进 bundle。

原题包全程只读。先运行题包探测并把探测表告诉我；缺 prompt、rubrics 或模型输出时停止，不猜路径。每个模型独立收集证据。没有真正隔离、禁网、无凭据、可丢弃副本和最小权限时，不要运行模型脚本或加载模型代码的探针。没有证据或存在口径歧义时写 null，不要为了填满而给 0。R1/R2 证据按轮次隔离，后续修复不能倒证前轮。最后必须运行 validator 和 package_bundle；只返回运行目录、就绪状态、待裁定项、证据缺口、ZIP、ZIP SHA-256 和退出码。
```

Agent 会先报告探测结果。`ok=true` 时这只是非阻塞进度更新，应自动继续初始化和取证；只有 `ok=false` 才停止。discovery 会自动排除模型最终输出目录和严格 `Rn` 快照目录中的 `prompt.md` 副本，并识别 `*模型对话*.json` 命名变体；只有过滤后仍不能唯一确定权威材料时才需要人工处理。关键材料缺失时，应优先修技能规则或提供明确路径映射，避免为了适配工具去修改原题包；确需改源时使用新的输出 run_id 重新开始，禁止在失败目录里混入新源文件。

## 3. 看懂远端结果

| 状态 | 含义 | 你该做什么 |
|---|---|---|
| `ready_for_form` / 退出码 0 | 结构完整，远端未发现未知或待人工项 | 复制 ZIP 到本机；本机仍会重验 |
| `ready_for_local_review` / 退出码 2 | 包可用，但有人工作业、待裁定或证据缺口 | 正常复制 ZIP；本机先生成裁定清单 |
| `incomplete` / 退出码 3 | 包结构、引用、哈希或证据覆盖错误 | 不复制评分；让远端按错误清单修复 |
| 退出码 4 | 运行中原输入变化 | 固定题包版本，换新 run_id 从头完整 export；禁止局部混合 |

退出码 2 不是失败。它表示脏活已完成，可以把剩余判断留给更可靠的本机模型和人工。

## 4. 在本机安装

本机同样需要 PowerShell 5.1+、Python 3.10+、Codex 本地文件与技能能力。在解压后的分发包目录运行：

```powershell
Set-ExecutionPolicy -Scope Process Bypass
.\install-local.ps1
```

这会安装 `vibe-evals-bundle-finalize`。安装后重启 Codex 或新建任务。

## 5. 本机首次处理 ZIP

```text
使用 $vibe-evals-bundle-finalize 处理证据包：
<ZIP绝对路径>

对应 SHA-256 文件：
<ZIP.sha256绝对路径>

先校验哈希、安全解压并在本机重跑 validator。若状态为 ready_for_local_review，只生成《人工裁定清单.md》和 evidence_requests.json，不要生成最终评分表单。向我逐项解释待裁定问题、证据、建议口径、备选口径和对各模型分数的影响。
```

## 6. 人工裁定

本机会优先让你处理三类事情：

1. 评分口径：criterion 存在两种合理解释。
2. 证据冲突：代码、自测、独立实测或 `记录.txt` 不一致。
3. 人工体验：视觉、可玩性、交互手感等不能只靠源码确认。

只需按清单回复。若同意技能建议，可以说“ADJ-001 按建议口径”；如果改判，说明采用哪个口径。技能会把你的决定写入独立审计文件，不会改证据 ZIP。

## 7. 需要补证时

把本机产生的 `evidence_requests.json` 复制到第三方机器，使用：

```text
使用 $vibe-evals-son-evidence-supplement。
基包目录：<第三方机器上已封印且未修改的原证据bundle目录；不要直接填ZIP>
源题包：<原题包路径>
补证请求：<evidence_requests.json路径>
输出：<全新delta目录>

只处理请求指定的模型和 rubric，不修改基包。先运行 `verify_source.py`；若源哈希变化，它以退出码 4 立即终止，本批次不得初始化或返回 delta，更不能把当前源码混入旧批次。无安全沙箱时不运行动态测试。完成后输出 delta ZIP、SHA-256 和每个请求的状态。
```

收到 delta ZIP 和 `.sha256` 后，把两者以及本机原始 `evidence_requests.json` 一起交给 finalize skill。原请求必须保留，不能用 delta 内的 `request-copy.json` 替换；本机会逐字节核对，防止远端改写补证范围。若远端 `verify_source.py` 以退出码 4 报告 `source_changed`，不会有合法 delta 可合并；需在第三方机器用新 run_id 重新跑完整 export。

## 8. 生成最终表单

所有 rubric 口径、证据缺口、material gaps 和人工检查闭环后使用：

```text
继续使用 $vibe-evals-bundle-finalize。按我已确认的人工决定生成 human-decisions.json，运行 finalize_scores.py 转录每模型 scored rubrics，然后生成反馈报告、rubrics 打分热力图和 Vibe Evals V2.1 单文件多模型评分表单。

先逐模型独立评总体印象，再生成 Rank；总体印象是第一排序键，可比 Rubric 表现得分只在总体印象相同时决胜。所有 pointwise 与总体印象机器建议继续标注“待人工确认”。交稿前重新核对 JSON、报告、热力图和表单数字。
```

## 9. 第三方 Agent 常见错误

- 未找到代码就给 0：要求改成 null，除非有确认缺失证据。
- 用最终代码给 R1 得分：要求回到 R1 结束快照。
- 无沙箱直接运行 `_check.js`：立即停止，标 `skipped_no_isolation`。
- 只给第三方绝对路径：要求附相对路径、原文件哈希、行号和连续摘录。
- 人工记录冲突时自己选边：要求建立 ADJ 待裁定项。
- 把完整源码和完整大对话塞进 ZIP：要求只带最小充分摘录、日志和哈希。
- 子代理说完成就生成 READY：必须以 validator 为准。
- 把 Rubric 表现排序当最终 Rank：本机表单必须重新按总体印象优先排序。

## 10. 安全与真实性说明

SHA-256 能证明复制后内容未变化，schema 能证明结构和引用一致，但不能数学证明第三方模型没有伪造摘录。因此本机仍会重点抽查分水岭条目、低置信度、人工改分和冲突证据。需要时走定向补证，而不是盲信远端报告。

证据 ZIP 越真实、轮次越准确、原始日志越完整，最终评分表单越可信；汇总技能不会用文笔掩盖证据缺口。
