# 本机裁定与真实性判断

> 适用范围：**v1 证据包与增量包**。form-ready 包的本机路径不产生任何裁定（见 [verify-and-render-runbook.md](verify-and-render-runbook.md)）；远端已经闭合的分数不要在本机重新裁定。

## 三档证据可信度

1. `bundle_verified`：连续源码摘录 + 行号 + 原文件哈希，或原始测试日志/人工原文齐全。可以作为评分事实。
2. `source_machine_only`：远端声称看过，但缺摘录、日志或哈希。只能作为补证线索，不能独立支持最终 0/1。
3. `requires_recollection`：引用断裂、轮次错位、哈希不一致、安全声明不可信。必须补证或重导出。

结构校验通过只证明数据自洽，不证明摘录没有被远端模型编造。对分水岭、人工改分和低置信度项优先抽查；可用补证让远端返回更大上下文或原始日志。

## 情况判断

| 情况 | 本机动作 |
|---|---|
| 远端建议 0/1 且证据直接、无冲突 | 可让用户接受机器建议 |
| 建议为 null | 不得自动换成 0；补证或人工裁定 |
| score 有 reason 但没有 evidence_id | 结构不合格，退回补证 |
| 静态支持、人工行为失败 | 行为类优先建议采信可复现人工结果；仍让用户确认 |
| 自测 PASS、探针 FAIL | 查场景覆盖；通常以更贴 rubric 的探针为强证据 |
| 人工记录未注明版本 | 不猜轮次；补证或裁定 |
| R1 失败、R2 修复 | 各轮各判；不能改写历史 |
| 主观条目只有代码 | 要求人工观察，不把代码美学推断当体验 |
| 兜底候选 | 查看重要实现覆盖与运行事实，由用户确认是否触发总分 0 |
| 不同模型 rubric 集不一致 | 建立共同条目或确认映射；无法可比时 Rank 次键不强排 |
| 远端报告数字和 JSON 不一致 | JSON 也不能直接信；以证据和重算结果修复后再继续 |

## 人工裁定写法

每项必须说明：问题、为什么两种理解都合理、证据、建议、备选、对所有模型的分数影响。用户选择后统一应用，不允许只为某模型放宽。

如果用户只回复“按建议”，把该原话记录在 resolution；不要扩写出用户没有说过的理由。

## 补证还是裁定

- 可通过更多源码上下文、原始日志、对话消息或指定实测得到事实答案：补证。
- 即使事实齐全仍取决于 criterion 含义或评分哲学：人工裁定。
- 同时存在事实缺口和政策歧义：先补事实，再裁定。

## 停止条件

以下任一存在就停止 finalization：包 incomplete、哈希失败、模型/rubric 覆盖不全、未知分、未决裁定、人工检查未完成、最终 reason 无证据、基线字段丢失、数字冲突或 Rank 使用不可比次键。
