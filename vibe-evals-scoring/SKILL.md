# Vibe Evals 打分流水线

## Overview

vibe-evals-rubric-review 的下游主技能：证据收集（并行子智能体）→ 机器预打分 → 人工打分文档 → 人工回填 → 逐条复核 → 转录 rubrics-{X}.json → 反馈报告 + 热力图。可独立运行（前置产物缺失时提示先跑 vibe-evals-rubric-review，用户坚持可降级并在报告注明）。支持两种入口：从零跑（Phase 0 起）与人工交回复核（从 Phase 4 起）。

## 通用骨架

以下三块为技能族共用骨架，本技能全文生效（标题层级已按本文件调整）：

### Phase 0: 题包探测（MANDATORY，任何材料收集前执行）

给定用户提供的题包根路径（如 `.../双曲空间的推箱子游戏-0816`），探测以下内容并向用户汇报，缺关键材料时**停下来问参数**，不猜：

1. **轮次记录目录**：`{题}轮次记录/`，内含：
   - `prompt.md` — 题目各轮 prompt（MANDATORY，缺则停）
   - rubrics 基线判定（按优先级）：`合并rubrics*.json` → 无则 `rubrics*.json` → 再 `原rubrics*.json`（MANDATORY，全无则停）
   - `{X}模型对话记录.json` — CodeBuddy 导出（每个模型一个，命名 `{X}模型对话记录.json`）
   - `记录.txt` — 评测人人工记录（可选，存在时其内容为**权威人工意见**）
   - `R1/`、`R2/`… 每轮每模型快照子目录（`R1/{X}/{题}-{X}/...`）
2. **模型输出目录**：`{题}-模型输出/`，每个子目录 = 一个模型（模型标识 = 子目录名），自动探测模型列表与模型数 N（支持任意 N）
3. **上批次分析**：上一批次目录中的《对每条rubric的理解.md》（可选；存在则复制并过目）。上一批次目录由用户提供（通常为题包同级的上批次目录）；复制到本批输出目录供后续相位对照。
4. **字段解释**：资料包 `rubrics说明.xlsx`（可选；存在则读取字段语义）
5. **输出目录**：用户指定（无指定则询问）；**若输出目录已有同名金标准产物，必须换新目录，绝不覆盖**

探测完成后输出「探测结果」表（每个材料：路径 / 状态 / 用途），让用户确认后再进入 Phase 1。

### MANDATORY 纪律（贯穿全流程）

1. **主会话不读模型源码**——模型证据收集全部使用 Codex `spawn_agent` 子智能体，主会话只接收结构化回报。每个模型保持独立取证责任；模型数超过可用并发槽位时分批派发，并用 `wait_agent` 等待完成；
2. **打分依据必须 file:line 或实测结果**——任何 0/1 判定必须引用具体文件行号或实测输出，不允许“看起来像是实现了”；
3. **机器不擅自裁定判分口径**——遇到需人拍板的判分问题，产出“待裁定项”（附证据+建议口径）供人工裁定，不自行定论；
4. **兜底 0 分规则**：无输出产物 / 几乎未实现 prompt 重要实现 → 该模型总体 0 分（写进报告，不逐条打分）；
5. **0/1 二值、每条 1 分、无权重**（Must have / Nice to have 仅作元数据，不参与加权）；
6. **“未经纠正时”语义** = 以模型当轮自主产出为准（未经评测方纠正即正确才得分）；
7. **不碰原文件**：新 rubric 写新文件；原 rubrics 与金标准产物永不修改，仅本流水线自产文件（rubrics1..N.json、对每条rubric的理解.md、预打分.md、人工打分文档.md、rubrics-{X}.json、反馈报告.md、rubrics打分热力图.html、验证探针、测试临时副本）可写；
8. **Python 环境**：Windows 下 `python` 不可用时用 `py` 启动器（`py -c "..."`），绝不因此中断。

### 交稿前检查（全部通过才交稿）（通用条目，以文末完整清单为准）

- [ ] （技能专属检查项，见文末）
- [ ] 输出文件齐全，路径与命名符合模板
- [ ] 所有分数/证据交叉一致（md 与 json 数字一致）
- [ ] 无未处理的待裁定项

> 本技能的专属检查项见文末「交稿前检查」一节。

## 前置检查：上游产物（Phase 1 之前）

执行顺序：题包探测 → 本前置检查 → Phase 1…6。

检查输出目录或题包内是否已有 vibe-evals-rubric-review 的产物（rubrics1..N.json + 对每条rubric的理解.md）；缺失则提示先跑该技能；用户坚持时降级用基线 rubrics 直接跑，并在反馈报告“判分口径说明”注明“未经 rubric-review 审查”。

## Phase 1: 证据收集（按模型独立派发，受可用并发槽位约束）

- 使用 Codex `spawn_agent` 为每个模型派发一个独立子智能体；模型数大于可用槽位时分批派发并用 `wait_agent` 等待。消息来自 [`templates/证据收集子智能体prompt模板.md`](templates/证据收集子智能体prompt模板.md)，替换 `{MODEL}` / `{RUBRICS_TEXT}` / `{MODEL_SOURCE_DIR}` / `{CONV_JSON_PATH}` / `{SNAPSHOT_DIRS}` / `{RECORD_TXT}` / `{OUTPUT_DIR}` 占位符；
- `{RUBRICS_TEXT}` 取前置检查确认的 rubrics（rubric-review 产物优先、否则基线）；`{RECORD_TXT}` 在 记录.txt 缺失时替换为“无”；
- 子智能体六项任务：
  1. 读模型源码定位证据（file:line）；
  2. 跑模型自带测试脚本（`_check.js` / `_api_test.js` 等，`node <脚本>` 实测并记录输出）；模型提供的脚本按不可信代码处理，仅在真正隔离、禁网、最小文件权限的环境中运行，详见证据收集子智能体prompt模板任务 2；
  3. 写临时验证探针：rubric 场景未被自测覆盖时，探针以 `_verify_{模型}_{条目id}.js` 命名**留档**在输出目录 `验证探针/` 子目录；任何会执行、加载、导入或求值模型产物代码的探针，都必须遵守与模型自带测试相同的隔离、禁网、无凭据、可丢弃副本和最小权限规则；无法隔离时只做静态验证或登记证据缺口，不得在宿主环境实跑；
  4. 解析 CodeBuddy 对话记录 json；
  5. 读记录.txt（提取该模型相关的人工实测意见）；
  6. 对照 R1/R2 轮次快照（重构轨迹、逐轮差异）。
- 回报格式（强制结构化）：每条 rubric → `{证据位置(file:line或实测输出), 实测结果, 判定倾向(0/1), 置信度(高/中/低)}`，外加该模型的对话摘要（各轮消息索引、自测与妥协决策、修复轨迹、会话统计 msg数/tokens/耗时）；
- 主会话不读模型源码，只汇总子智能体回报为“证据库”。

## Phase 2: 预打分（产 `预打分.md`，按 [`templates/预打分模板.md`](templates/预打分模板.md)）

- 逐模型逐条 0/1 + 定位（证据）+ 原因；判分规则：0/1 二值、每条 1 分、无权重、“未经纠正时” = 以当轮自主产出为准、兜底 0 分规则（MANDATORY 纪律第 4 条）；
- 口径问题不擅自拍板：沿用理解md 中裁定项的编号（①②③…），本批新发现的追加为新的裁定项编号，每项附建议口径；
- Subjective 条目：给证据 + 标注“建议人工实测确认”；
- 每模型末尾给汇总（得分/总条数 ≈ 比例 + 扣分条目列表）。

## Phase 3: 人工打分文档生成（产 `人工打分文档.md`，按 [`templates/人工打分文档模板.md`](templates/人工打分文档模板.md)）

- 每模型一节：id | 条目 | 证据提示（含证据 file:line 摘要） | 得分（预填预打分结果） | 备注（留空）；
- 顶部：打分说明（判分规则 + 兜底规则 + “未经纠正时”语义 + 实测优先原则）+ 待裁定项清单（与理解md 一致，本批新发现补充；无理解md 时仅列本批新发现裁定项）+ 回填指引（改分数写备注即可，可附自由意见）；
- 交人工填写，等待交回。

## Phase 4: 回填复核（人工交回人工打分文档后触发）

同一技能内支持“从零跑”与“交回复核”两种入口。交回时仍先执行 Phase 0 的**只读探测**，但不重跑 Phase 1–3；确认以下最小材料齐全后从本 Phase 开始：人工打分文档、对应的预打分、基线 rubrics、已有证据库或可重新取证的模型源码/对话/实测路径。缺任何一项则停下询问，不猜、不覆盖：

- 逐条 diff 人工分 vs 预打分，列出全部改动（改动清单）；
- **每处不一致重新取证核对**（人工不指明改动，机器必须一一核对）：重读该条相关源码/对话/实测证据，确认人工分有无新证据支撑，复核结论写“同意 / 存疑及理由”；重新取证同样使用 `spawn_agent`（复用 [`templates/证据收集子智能体prompt模板.md`](templates/证据收集子智能体prompt模板.md) 的单项任务变体），主会话只汇总回报；任何“存疑”都转为新的待裁定项并暂停 Phase 5–6，等待打分人二次裁定；
- 对话中的自由文本意见同步吃进，映射到对应条目/报告章节；
- 转录 `rubrics-{X}.json`（每模型一份，字段 = 基线 rubrics 字段 + `score` + `reason`）；**reason 口吻模仿用户本人**——参考记录.txt 的文风（用户手打），简洁陈述证据（如“落日渐变+透视网格+星空+扫描线+暗角+Orbitron 字体（game.js 504-540、style.css 22-33）”式写法），不写空话；记录.txt 缺失时用简洁的中文证据句（file:line 式）即可；
- 更新 `预打分.md` 顶部状态（注明“已于 {日期} 经打分人核查通过/改动 {n} 处”）；
- 逐项待裁定项标注“打分人裁定通过/改判”及最终口径，供 Phase 5 与交稿检查引用。

## Phase 5: 反馈报告（产 `反馈报告.md`，按 [`templates/反馈报告模板.md`](templates/反馈报告模板.md)）

1. 总体结论与 Rank：始终生成 rank 表（Rank | 模型 | Rubric 得分 | 总体分 | 一句话结论）。N≥2 时追加分差条目说明；N=1 时保留单行 Rank 表，并明确写“本批仅 {模型} 单模型，无排序/无同场比较”，不得写分差、并列或比较性结论。两种情况都写总分口径（得分/总条数，无权重，兜底规则适用情况）；
   - N≥2 的 Rank 规则（V2.1 3.2）：硬失败靠后（无法运行/核心链路阻断/严重违背显性约束明显靠后，局部亮点不能抵消）；只抓 1-3 个真正拉开差距的分水岭；只有交换位置也不改变推荐才并列；
2. 4W1H 问题定位：每个扣分/记录问题一条——What（现象）/Where（file:line 或多个模型各自位置）/When（哪轮引入、何时发现）/Who（哪个模型或共性）/How 修复（修复方向 + 判分）；
3. N≥2 时生成差异总表（维度行 = 产物/关键实现/自测规模/过程行为/会话规模/风格指纹/超预期/实测意见）+ 关键差异总结；N=1 时将其改为“模型表现 / 表现总表 / 表现总结”，不得使用比较性措辞；
4. 各模型 Rubric 打分明细（得分分布按轮、无权重说明）；N≥2 时追加分差矩阵（同判条数/分差条目列表），N=1 时不生成分差矩阵；
5. 判分口径说明（二值、兜底、“未经纠正时”、全部裁定项及最终口径）；
6. 对出题方的启示（rubric 与题面视角）；
7. 附录：关键实测证据表（证据 | 结果 | 来源）。

## Phase 6: 热力图（产 `rubrics打分热力图.html`，按 [`templates/rubrics打分热力图模板.html`](templates/rubrics打分热力图模板.html)）

分数卡（每模型得分/扣分摘要）+ Rank 卡 + 分组表格（按轮分组，绿 `td.ok`=1 红 `td.bad`=0）+ 图例（含无权重说明）。N=1 时 Rank 卡写单模型“无同场比较/无排序”，不得虚构比较列、分差或并列；N≥2 的 Rank 结果读 Phase 5，不另行计算。数据直接读 Phase 4 的 rubrics-{X}.json 与 Phase 5 的 rank 结果。

## 文字口吻与真实性（用户定稿 2026-08-21）

**反馈报告里的说明性散文——一句话结论、关键差异总结、4W1H 描述、对出题方的启示、裁定说明——以及 rubrics-{X}.json 的 reason，必须先读材料再写，句句有出处；禁止模板腔和“AI话”。**

- **口吻**：短句、事实、结论式，像评测人自己写的批注；禁止“总而言之/综上所述/需注意/值得一提的是”这类空转词和公文腔；
- **真实性**：每条结论必须回落到本批实际材料——rubric 编号、file:line、记录.txt 原文、对话 msg[n]、历史批次定稿分数；没有证据的话不写，没查到的标“未覆盖/无证据”，不编造、不空洞概括；
- **洞察/共性结论 = 跨模型看出来的共性问题或规律**：如“四个模型都没处理移动端断点，是这类题的共性缺口”——一句话事实结论，不是逐模型复述分数；
- **范本（2026-08-21 定稿表单，供散文部分参照）**：
  - “动画期丢键是四个模型共同的坑：C/D/GLM5.2/Hy3-dev 的 R1-08 全是 0……这条已经没区分度了”
  - “rubric 分和体感经常对不上……这种题评的是‘能不能玩起来’，不是条目加总”
  - “自测全绿不代表能玩……验证得覆盖真实操作路径”

**自检**：写完每段问一句“这是读了材料才写得出来的吗？换一批材料还能原样复用吗？”——能原样复用就是模板腔，重写。

## 交稿前检查（全部通过才交稿）

- [ ] 反馈报告数字与 rubrics-{X}.json 一致；人工打分文档得分与转录一致
- [ ] 无未处理的待裁定项（每项标注“打分人裁定通过/改判”）
- [ ] 热力图行数与 rubric 条数一致
- [ ] 输出文件齐全，路径与命名符合模板
- [ ] 所有分数/证据交叉一致（md 与 json 数字一致）
