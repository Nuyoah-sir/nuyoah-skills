# Vibe Evals Rubric 审查与理解

## Overview

读题包 rubrics + prompt，做三源核验（prompt 预期 → 模型效果 → 出题人思考），产出新 rubrics json（默认与基线逐字节一致）+ 《对每条rubric的理解.md》（含裁定口径）；本技能可独立运行，也是 vibe-evals-scoring 的前置。


## 前置条件（MANDATORY，任何材料收集前执行）

开跑前必须完成以下两项阅读，未完成不得进入 Phase 0：

1. **阅读多轮评测技能（multi-turn-eval）**：该技能在技能目录中——`~/.claude/skills/multi-turn-eval/SKILL.md` 或 `~/.agents/skills/multi-turn-eval/SKILL.md`（通常两处都有副本，找不到就问用户），通读其 SKILL.md。目的：明白该技能的输入（题目 spec 文件 / 模型输出目录 / 输出目录 / 模型对话目录，会话记录可选）、输出（反馈报告.md、Rubric.json、Rubric打分结果\Rubric_X打分结果.json、solution\solve_X.sh、tests\test.sh）与目的（多轮后端评测流水线：解析 spec → 生成 solve 脚本 + 黑盒 test.sh → Docker 逐模型评测 → 聚合评分），与本技能的人评路线（rubric-review → scoring → vibe-form）相区分；
2. **阅读人评标准**：本机《Coding Agent 人评标准 V 2.1》文档（题包随附材料或用户指定的位置，找不到就问用户取文件路径），重点读「二、打分流程指南」「三、多模型Rank（3.2 排序判断原则 / 3.3 排序理由怎么写 / 3.4 洞察怎么写）」「四、Pointwise 多维度评分」「五、Vibe Tags 与备注」。判分口径、Rank、洞察与备注的要求以此为准。

材料缺失或无法读取时**停下来问用户**，不猜、不跳过。

## 通用骨架

以下三块为技能族共用骨架，本技能全文生效（标题层级已按本文件调整）：

### Phase 0: 题包探测（MANDATORY，任何材料收集前执行）

给定用户提供的题包根路径（如 `...\双曲空间的推箱子游戏-0816`），探测以下内容并向用户汇报，缺关键材料时**停下来问参数**，不猜：

1. **轮次记录目录**：`{题}轮次记录/`，内含：
   - `prompt.md` — 题目各轮 prompt（MANDATORY，缺则停）
   - rubrics 基线判定（按优先级）：`合并rubrics*.json` → 无则 `rubrics*.json` → 再 `原rubrics*.json`（MANDATORY，全无则停）
   - `{X}模型对话记录.json` — CodeBuddy 导出（每个模型一个，命名 `{X}模型对话记录.json`）
   - `记录.txt` — 评测人人工记录（可选，存在时其内容为**权威人工意见**）
   - `R1/`、`R2/`… 每轮每模型快照子目录（`R1/{X}/{题}-{X}/...`）
2. **模型输出目录**：`{题}-模型输出/`，每个子目录 = 一个模型（模型标识 = 子目录名），自动探测模型列表与模型数 N（支持任意 N；MANDATORY，缺失则停）；
3. **上批次分析**：上一批次目录中的《对每条rubric的理解.md》（可选；存在则复制并过目）。上一批次目录由用户提供（通常为题包同级的上批次目录）；复制到本批输出目录供后续相位对照。
4. **字段解释**：资料包 `rubrics说明.xlsx`（可选；存在则读取字段语义）
5. **输出目录**：用户指定（无指定则询问）；**若输出目录已有同名金标准产物，必须换新目录，绝不覆盖**

探测完成后输出「探测结果」表（每个材料：路径 / 状态 / 用途），让用户确认后再进入 Phase 1。

### MANDATORY 纪律（贯穿全流程）

1. **主会话不读模型源码**——涉及模型源码或产物的证据收集使用 Codex `spawn_agent` 子智能体；主会话只接收结构化回报。若模型数超过可用并发槽位，按模型分批派发，仍保持每模型独立取证；
2. **打分依据必须 file:line 或实测结果**——任何 0/1 判定必须引用具体文件行号或实测输出，不允许“看起来像是实现了”；
3. **机器不擅自裁定判分口径**——遇到需人拍板的判分问题，产出“待裁定项”（附证据+建议口径）供人工裁定，不自行定论；
4. **兜底 0 分规则**：无输出产物 / 几乎未实现 prompt 重要实现 → 该模型总体 0 分（写进报告，不逐条打分）；
5. **0/1 二值、每条 1 分、无权重**（Must have / Nice to have 仅作元数据，不参与加权）；
6. **“未经纠正时”语义** = 以模型当轮自主产出为准（未经评测方纠正即正确才得分）；
7. **不碰原文件**：新 rubric 写新文件；原 rubrics 与金标准产物永不修改，仅本技能自产文件（rubrics1..N.json、对每条rubric的理解.md）可写；
8. **Python 环境**：Windows 下 `python` 不可用时用 `py` 启动器（`py -c "..."`），绝不因此中断。

- [ ] （技能专属检查项，见文末）
- [ ] 输出文件齐全，路径与命名符合模板
- [ ] 理解md 与 rubrics JSON 的 id、criterion、数量一致；若文档引用了分数，再核对分数与其来源一致
- [ ] 待裁定项全部登记（编号+证据+建议口径）

## Phase 1: 材料通读

按以下顺序通读全部材料：

1. **prompt.md**：把各轮要求逐条列出——轮次结构（共几轮、每轮主题）+ 每轮显式要求清单（该轮 prompt 对模型提出的每条要求，逐条编号），作为 Phase 2 对照查缺的基准；
2. **基线 rubrics**：读基线 rubrics json，记录条数、id 规律（如 `R1-09` 的轮次-序号规则）、各字段值域（criterion / round / priority / dimension / necessity / type 等字段的实际取值）；
3. **记录.txt**（若有）：通读，其内容为权威人工意见，后续引用时标注来源；
4. **rubrics说明.xlsx**（若有）：用 `py` + openpyxl 解析（如 `py -c "import openpyxl; wb = openpyxl.load_workbook(r'...'); ..."`），提取字段语义（id / section / round / criterion / type / necessity / priority / dimension / source 各字段含义）；
5. **上批次《对每条rubric的理解.md》**（若有）：通读，供 Phase 3 生成 ID 映射与 Phase 4 历史教训对照。

## Phase 2: 原 rubrics 三源核验

来源优先级：**prompt 预期 → 模型效果 → 出题人思考**。每条 criterion 的立身依据必须回落到三源之一。“出题人思考”只能来自用户明确说明、`记录.txt` 或其他已提供材料，不得由机器推断隐藏考点。

**证据收集方式**：涉及读模型源码/产物的核验使用 `spawn_agent` 派发子智能体；回报格式固定为「条目 id | 证据位置（file:line 或实测输出）| 结论」。主会话只汇总回报，不读源码。用 `wait_agent` 等待完成；模型数超过并发上限时分批派发，不合并不同模型的证据责任。

### 2.1 废话检测

- 每条 criterion 逐条回落到 prompt 找依据（对应哪轮哪句要求）；
- 找不到依据、且无法归为“出题人思考”（出题人有意埋的考察点）的条目 → 标记“疑似废话”并给出证据（条目原文 + 未能在 prompt 找到依据的说明）；
- **结论如实回答**：废话有就是有、没有就是没有，逐条给证据，不硬找问题。

### 2.2 不足检测

- 对照 prompt 关键要求逐条查缺——显式要求没考、隐含行为没考、端到端可玩性没考；
- 对照模型产物查口径问题（如“17 步场景在有限世界下不可执行”、几何不可达妥协）：criterion 描述的场景在模型产物中实际不可达成时，该条判分口径存疑，列入待裁定项；
- 每处缺口写明：缺哪条 prompt 要求、相邻 rubric 条目能否覆盖、建议补充位置。

### 2.3 冗余 ≠ 废话

证据面不同的细粒度条目（如 R1-09 视觉拼合 vs R1-13 拓扑闭环）标注“**保留**”并说明证据面差异；只有同一证据面、同一判分点的条目才算冗余。

## Phase 3: 产出新 rubrics1..N.json

1. 写入输出目录，文件名与基线对应（基线为 `合并rubrics1.json` / `合并rubrics2.json` 时产出 `rubrics1.json` / `rubrics2.json`，数量与基线一致）；
2. **默认与基线逐字节一致**：既定指示是不改、不增、不删；
3. 确有增改删建议时，只在理解md“1.3 修改策略”节**列出供用户批准**，绝不静默写入新 json；
4. 有上批次理解md 时生成 ID 映射表（旧批次 id → 新批次 id，如 0814→0816 轮次合并重排映射），写入理解md；
5. 写出后用 `py` 读回对比基线逐字节 diff，确认一致（或差异恰为用户批准的修改清单）。

## Phase 4: 逐条理解

按模板 [`templates/对每条rubric的理解模板.md`](templates/对每条rubric的理解模板.md) 产出《对每条rubric的理解.md》，每条 rubric 一节，包含：

- **考察意图**：这条 criterion 想考什么（一句话）；
- **依据来源**：标注三源之一——prompt 哪句（轮次 + 原文引用）/ 模型哪个效果（模型 + file:line 或实测）/ 出题人思考；
- **判分要点**：0/1 判定的关键证据与边界（什么情况判 1、什么情况判 0）；
- **本批模型证据**：本批各模型对应证据位置（file:line 或实测结果）。

有上批次分析时：**复制并过目**上批次《对每条rubric的理解.md》，逐条更新模型证据、保留历史教训对照（如 0814 B 伪投影教训）。

## Phase 5: 裁定口径

判分上需要人拍板的问题不自行定论，列成“待裁定项”（①②③…）：

- 每项 = 问题描述 + 证据（引用具体条目 / 模型产物 file:line / 实测结果）+ 建议口径（机器推荐怎么判，供人工参考）；
- 写入理解md“1.1 本批新发现的口径问题”节；
- 供 vibe-evals-scoring 预打分引用（该技能读理解md 的裁定节；口径问题不擅自拍板）。

## 文字口吻与真实性（用户定稿 2026-08-21）

**《对每条rubric的理解.md》里的说明性文字——总体结论、1.1 口径问题、1.3 修改策略、逐条理解的“考察意图/依据来源/判分要点”——必须先读材料再写，句句有出处；禁止模板腔和“AI话”。**

- **口吻**：短句、事实、结论式，像评测人自己写的批注；禁止“总而言之/综上所述/需注意/值得一提的是”这类空转词和公文腔；
- **真实性**：每条结论必须回落到本批实际材料——rubric 编号、file:line、记录.txt 原文、对话 msg[n]、历史批次定稿分数；没有证据的话不写，没查到的标“未覆盖/无证据”，不编造、不空洞概括；
- **洞察/共性结论 = 跨模型看出来的共性问题或规律**：如“四个模型都没处理移动端断点，是这类题的共性缺口”——一句话事实结论，不是逐模型复述；
- **范本（2026-08-21 定稿表单，供散文部分参照）**：
  - “动画期丢键是四个模型共同的坑：C/D/GLM5.2/Hy3-dev 的 R1-08 全是 0……这条已经没区分度了”
  - “rubric 分和体感经常对不上……这种题评的是‘能不能玩起来’，不是条目加总”
  - “自测全绿不代表能玩……验证得覆盖真实操作路径”

**自检**：写完每段问一句“这是读了材料才写得出来的吗？换一批材料还能原样复用吗？”——能原样复用就是模板腔，重写。
